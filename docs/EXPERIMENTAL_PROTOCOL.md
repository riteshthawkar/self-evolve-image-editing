# Experimental Protocol

This project should be read as **post-training on top of the released Qwen-Image-Edit-2509 checkpoint**, not as a reproduction of Qwen's original large-scale pretraining.

## Official Qwen-Matched Anchor

The paper-matched anchor is:

- model: `Qwen/Qwen-Image-Edit-2509`
- inference: Diffusers `QwenImageEditPlusPipeline`
- dtype: `bfloat16`
- generation: `num_inference_steps=40`, `true_cfg_scale=4.0`, `guidance_scale=1.0`, `negative_prompt=" "`, `num_images_per_prompt=1`
- GEdit scoring: upstream `backbone=gpt4o`, which maps to OpenAI `gpt-4.1` in the current GEdit `VIEScore` implementation
- no prompt polishing during benchmark export

This is implemented by:

```bash
bash scripts/export_gedit.sh --device cuda
bash scripts/score_gedit.sh --set scoring.scorer_secret_env_path=gedit_secret.env
bash scripts/export_imgedit.sh --device cuda
bash scripts/score_imgedit.sh
```

The official baseline output name is `qwen_edit_2509_official_diffusers`.

## Our Research Update

Our contribution is the self-evolving post-training layer:

```text
source image -> proposer -> official Qwen editor samples K candidates -> preservation-aware evaluator -> accepted edit pairs -> LoRA post-training
```

The self-evolve editor now uses the same official 2509 inference settings as the benchmark anchor. This matters because pseudo-labels should be generated by the same policy we claim to improve, not by an older wrapper with different resizing and denoising behavior.

The main method is `internal-cepr`, documented in [Internal CEPR Reward](INTERNAL_CEPR_REWARD.md). It uses only the editor's internal Qwen image-text features and Qwen VAE latents:

```bash
bash scripts/run_self_evolve_matrix.sh --variant internal-cepr --images-dir data/unlabeled/self_evolve
```

## Qwen-Style Preservation Pressure

The Qwen report emphasizes edit consistency through a multi-task setup that includes reconstruction pressure. Our post-training is much smaller, but the same principle is built into the manifest writer:

- accepted edit records train the model to follow instructions
- reconstruction replay records train the model to preserve unchanged input content
- default replay ratio in Qwen self-evolve configs: `0.15`

This is not a claim that we reproduce Qwen's original training recipe. It is a controlled post-training analogue of the same preservation principle.

## Required Controls

Report these separately:

- `Official Qwen baseline`: `qwen_edit_2509_official_diffusers`, official Diffusers inference, no training.
- `Trainable-backend control`: base Qwen through the same train/eval backend used by the LoRA checkpoint, if a trained checkpoint cannot be loaded by official Diffusers.
- `Ours`: self-evolve-selected LoRA/full checkpoint.
- `Ablations`: plain proxy reward, weighted hybrid reward, spatial-only, cycle-only, internal-only, hard-gated relative ranker.

Do not compare a DiffSynth-loaded LoRA directly against the official Diffusers baseline without also reporting the trainable-backend control. Otherwise backend differences can be mistaken for method gains or losses.

## Contract Check

Run this after pulling changes or editing configs:

```bash
bash scripts/check_experiment_contract.sh
```

The check validates:

- GEdit and ImgEdit use official 2509 Diffusers settings.
- Self-evolve candidate generation uses the same official 2509 settings.
- Training configs use source-image conditioning through `edit_image`.
- Reconstruction replay is enabled for Qwen self-evolve configs.

If this check fails, do not start a long GPU run until the mismatch is intentional and documented.
